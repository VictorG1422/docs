# How the code works, module by module

| Module | Responsibility |
| --- | --- |
| `config/settings.py` | `Settings` (`pydantic-settings`) loads local/bootstrap settings from environment variables / `.env`; `get_settings()` applies only the explicit AWS credential/infrastructure allow-list. PostgreSQL dashboard settings own token-based watchlists, trading mode, risk, and scoring configuration; saved DB values override corresponding local settings. Validators reject invalid/overlapping watchlist token IDs, unsupported modes, and live mode without Kite API/access-token credentials. `SCALP_*` fields (`scalp_enabled`, `scalp_swing_bars`, `scalp_rr_min`, `scalp_atr_period`, `scalp_rsi_period`) control the 1-min scalp signal scanner and are overridable from the dashboard. |
| `trading_system/app_state.py` | `AppState` (`STARTING`/`WAITING_FOR_MARKET`/`WARMING_UP`/`RUNNING`/`MARKET_CLOSED`/`ERROR_RETRY`) and a thread-safe `ApplicationStateStore` holding the current snapshot (mode, state, market_open, next_open, reason_closed, last_candle_time, last_error) read by `GET /api/status`. |
| `trading_system/application.py` | `Application` composes PostgreSQL, Redis, Kite, subscriptions, and market data, refreshes required instruments, and starts the configured workflow (`paper` or `live` — no longer a "backtest" startup mode). A background supervisor thread drives the market-hours state machine for the rest of the process's life: it builds/starts the paper/live runtime when the market opens, tears it down at close, and waits for the next session — the process itself never exits because the market is closed. The configured runtime selects a `BaseStrategy` and runs `StrategyEngine` → `RiskEngine` → `OrderExecutionEngine`; live mode additionally reconciles persisted entry lots and broker net exposure. A shared Redis-backed entry pause applies across both modes; live orders still require independent execution safeguards. |
| `trading_system/health.py` | `HealthCheck` is a small named-check registry (`register`/`run`); `build_default_health_check()` registers only the `application` check for now (`Application` registers `postgresql`/`redis`/`kite`/`instrument_data`/`market_data_feed` separately). |
| `trading_system/main.py` | Algorithm-only CLI (`python -m trading_system.main`). Loads settings, applies dashboard-managed database overrides, starts `Application` (which owns the market-hours supervisor thread), and only waits for an explicit `SIGINT`/`SIGTERM` to stop — it does not exit on market close and does not start an HTTP server itself. |
| `dashboard/main.py` | Standalone FastAPI dashboard launcher (`python -m dashboard.main`); serves the UI/API and reads shared PostgreSQL/Redis state without starting a trading runtime. |
| `trading_system/broker/base.py` | `Broker` ABC -- `connect`, `get_instruments`, `subscribe`/`unsubscribe`, `place_order`/`modify_order`/`cancel_order`, `get_positions`/`get_orders`. Nothing outside `broker/` may import `kiteconnect`. |
| `trading_system/broker/kite_client.py` | **(Phase 4, extended Phase 6)** `KiteBroker`, the only `Broker` implementation, wrapping `kiteconnect.KiteConnect`. The access token is set on the underlying `KiteConnect` client eagerly in `__init__` (not only in `connect()`) so `health_check()`/`get_instruments()`/etc. all work correctly regardless of which method is called first. Retries `get_instruments()` on `BrokerConnectionError` with `tenacity`. `health_check()`, `login_url()`/`generate_access_token()`, and `_translate_kite_exception()` map every `kiteconnect.exceptions.*` error onto a typed `BrokerError` subclass. `get_historical_data()` (Phase 6) wraps `historical_data()`, mapping `interval_minutes` to Kite's interval strings -- deliberately not on the `Broker` ABC. |
| `trading_system/broker/websocket.py` | **(Phase 4)** `KiteWebSocketClient` wraps `kiteconnect.KiteTicker`, forwarding decoded ticks to a callback (normally `TickProcessor.process`). Logs connection/subscription attempts without credentials, deduplicates wire subscriptions, tracks `ConnectionState`, uses bounded reconnect (`KITE_MAX_RECONNECT_ATTEMPTS`), restores active subscriptions after reconnect, and marks failed clients unusable so the broker can replace them. Application shutdown closes the Kite socket. |
| `trading_system/market_data/tick_processor.py` | **(Phase 4, tightened Phase 6)** `MarketState` (thread-safe current/previous tick per instrument, plus `status()` for FRESH/STALE/UNAVAILABLE classification) and `TickProcessor` (validates ticks, updates state, optionally writes to a `MarketStateStore`, fans out to listeners, swallows per-listener/Redis exceptions). Validation rejects zero/negative price, negative volume/OI, and impossible intraday open/high/low ranges. Kite's quote `close` is the prior session's close and is intentionally excluded from intraday-range checks. |
| `trading_system/market_data/instrument_sync.py` | **(Phase 4; extended)** `InstrumentSyncService.sync()` -- `Kite -> validation -> InstrumentRepository -> PostgreSQL`. Upserts by `instrument_token` and prunes absent, unreferenced instruments within the same exchange transaction. Empty or invalid snapshots skip pruning; referenced trading/reconciliation history remains intact. Returns created/updated/skipped/removed/retained counts. `sync_required_exchanges()` refreshes NSE then NFO and raises on failure so trading cannot proceed with incomplete data. Preserves zero lot/tick values for `INDICES` reference rows only; other instruments require positive values. |
| `trading_system/market_data/nse_holiday_calendar.py` | Fetches NSE CM/FO holiday dates at algorithm startup, upserts them idempotently to PostgreSQL, and falls back to persisted holidays if NSE is unavailable. |
| `trading_system/storage/db/watchlist_migration.py` | Safe, audited conversion of legacy symbol-based PostgreSQL watchlists to synchronized underlying EQ tokens. Ambiguous or missing matches block the entire apply operation; the CLI defaults to dry-run. |
| `trading_system/market_data/subscription_manager.py` | **(Phase 4)** `SubscriptionManager` -- tracks the active instrument-token subscription set through the `Broker`, making `subscribe`/`unsubscribe`/`unsubscribe_all` idempotent. Independent of strategy logic. |
| `trading_system/market_data/underlying_discovery.py` | **(Phase 5)** `UnderlyingDiscoveryService.discover()` resolves a symbol (e.g. `NIFTY`) to an `UnderlyingInstrument` from synchronized PostgreSQL data -- never re-downloads from Kite. `is_supported()` checks the actual synced instrument data, never a hardcoded allowlist -- works for any NSE F&O underlying (index or single-stock), not only NIFTY/BANKNIFTY. |
| `trading_system/market_data/expiry_service.py` | **(Phase 5)** `ExpiryService` -- `get_available_expiries`/`get_expiries_between`/`get_nearest_expiry`/`get_next_expiry`, reading real synchronized expiry dates (no fixed weekly/monthly assumption), using the application's IST clock so an expired contract is never "nearest". |
| `trading_system/market_data/option_chain_service.py` | **(Phase 5)** `OptionChainService` -- the option-chain/contract-lookup facade: `get_available_strikes`, `get_call_contract`/`get_put_contract`/`get_contract` (deterministic), `get_option_chain`. Optional Redis read-through cache; PostgreSQL always authoritative. |
| `trading_system/market_data/market_data_service.py` | **(Phase 6, extended)** `MarketDataService` -- the market-data read/write facade with a runtime candle-token allowlist. Quote ticks reach protective listeners for all subscriptions; only configured signal/gate instruments aggregate and persist candles. |
| `trading_system/market_data/candle_aggregator.py` | **(Phase 6, extended)** `CandleAggregator` -- per-instrument OHLCV aggregation, cumulative-to-delta volume conversion, late-tick rejection, completion listeners, and optional NSE-session-open alignment for 30m/60m/4h/daily bars. |
| `trading_system/market_data/historical_data.py` | **(Phase 6, extended)** `HistoricalMarketDataProvider` -- normalizes Kite OHLCV and derives 4h bars from completed 60m data because Kite has no native 240m interval. |
| `trading_system/market_data/indicators.py` | **(Phase 6, extended)** SMA, EMA, RSI, MACD, ATR, VWAP, and Bollinger Bands delegate to `pandas-ta-classic` over timezone-aware pandas data, then convert results to stable Decimal result dataclasses; insufficient history returns `None`. |
| `trading_system/market_data/pivot_levels.py` | Calculates classic `P`, `BC`/`TC`, `R1`-`R3`, and `S1`-`S3` from a completed 1440-minute candle; selects only a daily candle from a strictly earlier IST session and exposes CPR bounds/width. |
| `trading_system/market_data/instrument_manager.py` | `InstrumentManager` caches/looks up `Instrument` records from the broker's instrument dump (by token or trading symbol). |
| `trading_system/market_data/option_chain.py` | Builds a strikes-by-expiry option chain view on top of `InstrumentManager` for CE/PE lookups. |
| `trading_system/strategy/base.py` | Configured strategy interface: `BaseStrategy.evaluate(context: MarketContext) -> StrategyDecision | None`. |
| `trading_system/strategy/context.py` | `MarketContext` -- the immutable per-evaluation snapshot, including candles, current price, status, strategy state, confirmation candles, and optional previous-session pivot levels. |
| `trading_system/strategy/decision.py` | `StrategyDecision` -- a strategy's raw output before the engine turns it into a formal `Signal`. |
| `trading_system/strategy/config.py` | `StrategyConfig` -- named, documented, testable per-strategy configuration (timeframe, candle lookback, persistence toggle, `confirmation_timeframes_minutes` for multi-timeframe strategies). Strategy-layer cooldown is not wired here; the risk layer's `RiskPolicy.cooldown_seconds` is the sole cooldown enforced. |
| `trading_system/strategy/no_op_strategy.py` | `NoOpStrategy` -- intentionally returns no decision; available as the `no_op` setting to disable signal generation. |
| `trading_system/strategy/patterns.py` | Pandas TA Classic candlestick detectors plus explicit swing-structure/H&S rules; also the home of `oi_buildup`/`volume_spike`/`vwap_bias`, reused directly by the triggers/filters below. |
| `trading_system/strategy/scoring.py` | `ScoringConfig` -- every tunable the regime/trigger/filter engine needs (regime thresholds, trigger/aging parameters, time-of-day windows, gap-resolution config), built from `config.settings.Settings` via `ScoringConfig.from_settings`. No scoring/weighting logic lives here; it's configuration only. |
| `trading_system/strategy/regime.py` | The regime state machine: `RegimeState` (`TREND`/`TREND_AGING`/`CHOP`/`NEUTRAL`/`DISABLED`), `evaluate_regime()`, and the TREND_AGING sub-conditions (running-extreme age, VWAP cross count, ADX drop from peak). |
| `trading_system/strategy/triggers.py` | The entry triggers: T1 opening-range breakout and T3 VWAP pullback (T2 gap resolution reuses `technical_scoring_strategy.py`'s existing gap-context detector directly). |
| `trading_system/strategy/filters.py` | The entry filters F1 (flow), F2 (60m higher-timeframe confirmation), F3 (exhaustion), F4 (time of day), and F5 (counter-trend flip, with hysteresis). |
| `trading_system/strategy/technical_scoring_strategy.py` | `TechnicalScoringStrategy` -- `evaluate()` runs the single pipeline (`regime.py` + `triggers.py` + `filters.py`, no score threshold anywhere). Records a full diagnostic snapshot (`last_result`) on every evaluation including `regime_inputs` (all computed indicator values: ADX, choppiness index, directional efficiency, ATR, ATR percentile) so the candle-evaluation panel in backtests and paper sessions shows the raw indicator readings alongside regime/trigger/filter results. |
| `trading_system/strategy/signal_factory.py` | **(Phase 7)** `build_signal_dedup_key()`/`build_signal()` -- the only place a `Signal`'s deterministic identity and field-mapping are constructed; `instrument_token`/`tradingsymbol` come from `option_contract` when set, never the underlying's own. |
| `trading_system/strategy/option_selector.py` | **(Phase 7)** `OptionSelector` -- translates an underlying `BUY`/`SELL` signal into a concrete CE/PE `OptionContract` (ATM/OTM/ITM, nearest/min-days expiry) via Phase 5's `OptionChainService`/`ExpiryService`. Always buys (CE for `BUY`, PE for `SELL`) -- never writes/sells naked options. |
| `trading_system/strategy/signal_validator.py` | **(Phase 7)** `validate_signal()` -- pure validation function (no I/O), returns a list of failure reasons. |
| `trading_system/strategy/strategy_engine.py` | **(Phase 7)** `StrategyEngine` -- the orchestrator: candle-completion trigger, staleness gate, distributed lock, dedup, option-contract resolution (`_resolve_option_contract`, optional `OptionSelector`), validation, persistence, state update. Terminates at "signal generated" -- never calls risk/order/broker code. Persists `regime_inputs` from each strategy evaluation into the `gate_inputs` column of `StrategyEvaluationDiagnostic` so the dashboard diagnostic panel displays full indicator readings. |
| `trading_system/risk/policy.py` | `RiskPolicy` -- every limit defaults to `None` ("not enforced") except where a safe default makes sense (stop-loss/target); `from_settings()` builds one from `Settings`' `RISK_*` fields. `trailing_exits_enabled` defaults to `True` (matches the `Settings` default). Carries the daily-circuit-breaker fields, idea-clustering/risk-budget fields, `entry_mode`, and partial-exit/time-stop fields. |
| `trading_system/risk/risk_decision.py` | `RiskCheckStatus`/`RejectionReason`/`RiskCheckOutcome`/`RiskDecision` -- the auditable result of one risk evaluation; includes `DAILY_CIRCUIT_BREAKER_TRIGGERED` among the rejection reasons. |
| `trading_system/risk/account_state.py` | `AccountState`/`AccountStateProvider`/`PostgresAccountStateProvider` -- exposure/P&L/position-count/daily-trade-count/`consecutive_losses_today`/`open_risk_amount` derived from durable PostgreSQL records; broker capital/margin always `None`. `backtest/paper.py::PaperPortfolioAccountStateProvider` computes the same fields from the simulated portfolio for paper/backtest. |
| `trading_system/risk/position_sizer.py` | `PositionSizer` -- `Decimal`-precise, lot-size-floored quantity calculation from risk/capital/exposure/quantity limits; also applies the daily-circuit-breaker half-size action and any `size_multiplier` a signal carries (TREND_AGING half-action, F5's 50%-size reversal), flooring to a whole lot or rejecting if that floors to zero. |
| `trading_system/risk/position_state.py` | `PositionLifecycleStatus`/`RiskPositionStateStore` -- `NONE`/`PENDING`/`PARTIAL`/`OPEN`/`CLOSING`/`CLOSED` semantics layered on the Redis `PositionStateStore`. |
| `trading_system/risk/risk_engine.py` | `RiskEngine` -- the ordered risk-check pipeline: `Signal -> RiskDecision -> TradeIntent`. Appends (never reorders/removes) checks as new features are added: idea clustering (one entry per underlying+direction within a configurable window, `risk_legacy_pyramiding_enabled` restores the old unlimited behavior), the daily circuit breaker, per-idea and total-open-risk budgets, on top of the original market-data/window/duplicate/cooldown/daily-loss/daily-trades/exposure/stop-loss/target/risk-reward/sizing checks. Never places an order and fails safe on storage/Redis errors. |
| `trading_system/risk/stop_loss.py` | `StopLossCalculator`/`TargetCalculator` -- ATR-based (with percentage fallback) or points-based stop-loss, and a reward:risk-derived target. Fully configurable/disable-able via `RiskPolicy`. Both values are quantized to 2 decimal places so the value computed here always matches what gets persisted and re-validated downstream. |
| `trading_system/models/trade_intent.py` | `TradeIntent`/`TradeIntentStatus` -- the risk engine's sole output, consumed by order execution. |
| `trading_system/storage/redis/risk_state.py` | `RiskRuntimeStateStore` -- non-authoritative atomic daily counters + cooldown markers; PostgreSQL remains authoritative. |
| `trading_system/storage/redis/execution_state.py` | `ExecutionRuntimeStateStore` -- expiring recent execution cache only; PostgreSQL remains authoritative. |
| `trading_system/storage/redis/order_entry_control.py` | Shared operator entry-pause latch in Redis. Runtime pre-checks avoid unnecessary entry/risk work; `OrderExecutionEngine` is the final check. Redis read failure is fail-closed for entries; exit intents bypass the entry pause. |
| `trading_system/execution/order_request.py` | Broker-neutral `OrderRequest`, execution lifecycle/result, and broker order snapshot types. |
| `trading_system/execution/broker_adapter.py` | `BrokerOrderAdapter`, `KiteBrokerAdapter`, and the paper adapter; the Kite adapter alone submits through the `Broker` abstraction. |
| `trading_system/execution/order_execution_engine.py` | Validates persisted approved intents, gates live submission, uses durable idempotency/Redis locks, submits once, and records unknown/fill status. |
| `trading_system/execution/broker_status.py` | `map_broker_status()`/`legacy_status_for()`/`LEGAL_STATUS_TRANSITIONS` -- the single broker-status classification order execution's `refresh_status()` and reconciliation's `OrderReconciler` both use, so they can never disagree. |
| `trading_system/execution/order_tag.py` | `build_order_tag()` -- the deterministic broker order tag submitted on order placement and recomputed during reconciliation to resolve `SUBMISSION_UNKNOWN` without fabricating an association. |
| `trading_system/reconciliation/models.py` | **(Phase 10)** `ReconciliationResult`/`ReconciliationStatus`/`ReconciliationScope`, `OrderReconciliationItem`/`OrderReconciliationOutcome`, `PositionReconciliationItem`/`PositionReconciliationOutcome`, `ReconciliationResolution`. |
| `trading_system/reconciliation/policy.py` | **(Phase 10)** `ReconciliationPolicy` -- the centralized, explicit allow-list of safe auto-sync categories; `is_safe_position_quantity_sync()` encodes the "never auto-sync an unexpected quantity increase" rule. |
| `trading_system/reconciliation/order_reconciler.py` | **(Phase 10)** `OrderReconciler` -- compares `Broker.get_orders()` against persisted `orders`, including `SUBMISSION_UNKNOWN` tag-based resolution. Never calls a broker order-placement method. |
| `trading_system/reconciliation/position_reconciler.py` | **(Phase 10, extended)** `PositionReconciler` -- compares aggregate broker positions against sums of persisted live entry lots. Unsafe direction/quantity mismatches require manual action; it never submits a broker order. |
| `trading_system/reconciliation/engine.py` | **(Phase 10)** `ReconciliationEngine` (locking, orchestration, audit persistence, Redis runtime refresh) and `PeriodicReconciliationScheduler` (opt-in background thread). |
| `trading_system/storage/postgres.py` | `PostgresClient` wraps a SQLAlchemy engine + session factory (`session()` context manager commits/rolls back automatically) and exposes `health_check()`. Schema changes go through Alembic, never `create_all()`. Redacts the DSN from any connection-error text before logging/raising. |
| `trading_system/storage/db/base.py` | **(Phase 2)** `Base` (SQLAlchemy `DeclarativeBase`), `utcnow()`, and `TimestampMixin` shared by all ORM models. |
| `trading_system/storage/db/models.py` | **(Phase 2; extended Phase 8/9/10/11)** ORM models include `Instrument`, `Signal`, `Order`, `Position`, `Trade`, risk decisions/intents, append-only Phase 9 execution attempts, Phase 10's append-only `ReconciliationRun`/`OrderReconciliationRecord`/`PositionReconciliationRecord`, and `ScalpSignalLog` (migration 0027) which persists every scalp signal fired during live/paper sessions. Separate from Pydantic domain models. |
| `trading_system/storage/db/repositories.py` | **(Phase 2, extended Phase 5/6/10)** `BaseRepository` + one repository per model (`InstrumentRepository`, `SignalRepository`, `OrderRepository`, `PositionRepository`, `TradeRepository`, `CandleRepository`, and Phase 10's `ReconciliationRunRepository`/`OrderReconciliationRecordRepository`/`PositionReconciliationRecordRepository`); operates on an injected `Session`, never manages transactions itself. `InstrumentRepository` gains discovery queries in Phase 5. `CandleRepository` (Phase 6) adds `get`/`list_range`/`save_if_new` (idempotent) for completed candles. `SignalRepository` (unchanged interface; the underlying `Signal` ORM gains a Phase 7 `status` column) persists Phase 7 signals via `create()`. |
| `trading_system/storage/redis/client.py` | **(Phase 3)** `RedisClient` -- pooled `redis.Redis` connection (explicit `ConnectionPool`), `health_check()`, and graceful `close()`/`dispose()`. Never opens a real connection until first used. |
| `trading_system/storage/redis/keys.py` | **(Phase 3)** `RedisKeyBuilder` -- the single place that builds namespaced Redis keys (`trading:{environment}:{kind}:{id}`); nothing else in the codebase builds raw key strings. |
| `trading_system/storage/redis/serialization.py` | **(Phase 3)** Explicit JSON `dumps`/`loads` helpers -- never `pickle`; `datetime`/`date` become ISO strings, `Decimal` becomes a string (exact precision preserved), `Enum` becomes its value. |
| `trading_system/storage/redis/state.py` | **(Phase 3)** `RedisStateManager` -- generic `set`/`get`/`delete`/`exists`/`expire`/`set_json`/`get_json`, wrapping every Redis error as `RedisUnavailableError`. All higher-level stores build on this. |
| `trading_system/storage/redis/lock.py` | **(Phase 3)** `DistributedLock` -- `acquire_lock`/`release_lock` using atomic `SET NX EX` plus a per-holder token checked via `WATCH`/`MULTI` on release, so a lock can never be released by a non-owner. TTL-bounded so a crashed process can never hold it forever. |
| `trading_system/storage/redis/dedup.py` | **(Phase 3)** `DeduplicationStore` -- atomic `check_and_mark`/`is_duplicate` (via `SET NX EX`) for duplicate signal/event protection. |
| `trading_system/storage/redis/market_state.py` | **(Phase 3)** `MarketStateStore` -- `set_latest_tick`/`get_latest_tick`/`delete_latest_tick`, always TTL'd (transient by nature). Storage interface only -- no Kite WebSocket wiring yet. |
| `trading_system/storage/redis/strategy_state.py` | **(Phase 3)** `StrategyStateStore` -- `get_state`/`set_state`/`update_state`/`clear_state` for opaque per-strategy runtime state, no TTL by default. |
| `trading_system/storage/redis/position_state.py` | **(Phase 3)** `PositionStateStore` -- fast-access `get_position`/`set_position`/`delete_position` cache; PostgreSQL remains the authoritative position store. |
| `trading_system/storage/redis/cache.py` | **(Phase 3)** `CacheStore` -- generic, explicit-purpose `set`/`get`/`delete` with a default TTL, for instrument/option-contract/derived-data caching. |
| `trading_system/storage/redis/option_chain_cache.py` | **(Phase 5)** `OptionChainCacheStore` -- `get_option_chain`/`set_option_chain`/`delete_option_chain`, keyed by `RedisKeyBuilder.option_chain(underlying, expiry)`, TTL'd (60s default). A performance cache only -- PostgreSQL remains authoritative. |
| `trading_system/storage/redis/candle_cache.py` | **(Phase 6)** `CandleCacheStore` -- `get_latest_completed_candle`/`set_latest_completed_candle`/`delete_latest_completed_candle`, keyed by `RedisKeyBuilder.candle(instrument_token, interval_minutes)`, TTL'd (300s default). Caches only the latest *completed* candle, never the forming one. |
| `trading_system/storage/s3.py` | `S3Client` wraps `boto3` S3 operations for snapshot/archival storage; exposes `health_check()`. |
| `trading_system/models/*.py` | Pydantic v2 models: `Tick`, `Instrument`, `OptionContract` (Phase 5 -- `Decimal` strike/tick_size), `Candle` (Phase 6 -- `Decimal` OHLC, mutable), `Signal` (+ `SignalType`), `Order` (+ `OrderStatus`/`OrderType`/`ProductType`/`TransactionType`), `Position` (+ `PositionStatus`). These are the only data shapes passed between layers. |
| `trading_system/backtest/models.py` | **(Phase 11)** `BacktestConfig`, `BacktestResult`, `BacktestStatus`, `TradeRecord`, `DataQualityWarning`, `ExecutionModelConfig`, `PaperSessionStatus`. |
| `trading_system/backtest/costs.py` | **(Phase 11)** `TransactionCostModel` -- every rate defaults to zero/`verified=False`; never an invented real fee schedule. |
| `trading_system/backtest/data_loader.py` | **(Phase 11)** `HistoricalDataLoader` -- prefers PostgreSQL candles, falls back to the existing Phase 6 `HistoricalMarketDataProvider`; validates ordering/duplicates/missing intervals/invalid OHLC. |
| `trading_system/backtest/execution_adapter.py` | **(Phase 11)** `BacktestExecutionAdapter`/`PaperExecutionAdapter` -- implement the existing Phase 9 `BrokerOrderAdapter` interface with documented, conservative simulated fills; never call a real broker. |
| `trading_system/backtest/portfolio.py` | **(Phase 11)** `Portfolio` -- Decimal cash/P&L/equity/drawdown accounting with positions keyed by entry intent, preserving independent stop/target and close selection even when one instrument has multiple distinct index CE/PE entries. |
| `trading_system/backtest/metrics.py` | **(Phase 11)** Win rate/profit factor/consecutive win-loss/Sharpe/Sortino -- every metric is `None`, never fabricated, when the data is insufficient. |
| `trading_system/backtest/engine.py` | `BacktestEngine` -- wires the strategy/risk/execution engines against an isolated per-run SQLite database + in-memory Redis and simulated clock. Supports a cooperative `cancel_check` (checked at every candle boundary for the Stop button), a `progress_callback` (candle index/timestamp, polled by the dashboard), and force-closes open positions with `exit_reason=BACKTEST_STOPPED` on a smooth stop. Logs one structured line per processed candle and embeds a candle log + equity curve into the persisted result. After the main replay completes, `_collect_scalp_signals()` runs the 1-min scanner over the same date range (if a `scalp_config` dict is supplied) and stores the results in `result.metadata["scalp_signals"]`, which is serialized into `result_summary` in the database. The dashboard exposes these via `GET /api/backtest-runs/{run_id}/scalp-signals`. |
| `trading_system/backtest/entry_triggers.py` | `PendingEntryTracker` -- backtest-only implementation of the `break_of_signal_bar_high`/`pullback_entry` conditional entry modes (`risk_entry_mode`); live/paper always fill at `next_open` regardless of this setting. |
| `trading_system/backtest/export.py` | Builds every sheet of the per-run XLSX/CSV export (Run Summary, Config Snapshot, Candle Log, Signals & Risk Audit, Trades, Equity Curve, Daily Summary, Rejected and Blocked, Data Quality, Run Log) from the run's persisted data, with every cell passed through `utils/formatting.round2`. |
| `trading_system/backtest/paper.py` | `PaperTradingSession`/`PaperPortfolioAccountStateProvider` -- per-instrument strategy engine over an injected shared portfolio/session, quote-tick protective exits and pending-order refresh, Redis flat-state cleanup, configurable square-off no later than 15:00 IST, and the same `consecutive_losses_today`/`open_risk_amount` account-state fields the live/backtest risk checks rely on. |
| `trading_system/execution/live_trading_runtime.py` | Configured live signal runtime: composes strategies, risk, broker execution, reconciliation, per-entry protective exits, equity long-only exits, and options intraday square-off. Daily equity history is warmed before strategy evaluation; broker exposure remains netted per instrument, so per-entry exits are checked against the reconciled aggregate before submission. When `SCALP_ENABLED` is true and 1-min candle aggregation is active, one `ScalpSignalService` is registered per watchlist instrument and fires `SCALP_SIGNAL_FIRED` events on each completed 1-min bar throughout the session. |
| `trading_system/execution/exit_intents.py` | Builds persisted, risk-auditable protective/manual exit intents and records `execution_purpose`, `exit_reason`, and the selected `position_id` where applicable. |
| `trading_system/storage/db/models.py::Position` | Durable live position lot with entry-order linkage and per-entry stop/target; broker reconciliation compares summed lots with the broker's net exposure. |
