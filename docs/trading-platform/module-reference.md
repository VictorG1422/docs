# How the code works, module by module

| Module | Responsibility |
| --- | --- |
| `config/settings.py` | `Settings` (`pydantic-settings`) loads all configuration from environment variables / `.env`. **Exception**: every value (Kite credentials, Postgres/Redis, trading mode, risk policy, watchlist, scoring) is always overridable from a single AWS Secrets Manager secret -- `get_settings()` overwrites `kite_api_key`/`kite_api_secret`/`kite_access_token` unconditionally and everything else only for keys actually present in the secret (see [AWS Secrets Manager](setup.md#aws-secrets-manager)). A `field_validator` rejects unsupported `TRADING_MODE` values and a `model_validator` refuses to start if `TRADING_MODE=live` is set without `KITE_API_KEY` + `KITE_ACCESS_TOKEN` (both raise `ConfigurationError`). `get_settings()` is an `lru_cache`d factory used everywhere instead of constructing `Settings()` directly. |
| `trading_system/application.py` | **(Phase 1-6)** `Application` is the current composition root: `start()` logs configuration/trading mode and marks the app running; `stop()` unsubscribes all active tokens and disposes the PostgreSQL/Redis clients. Constructs a `PostgresClient`, a `RedisClient`, and a `KiteBroker`, and registers `postgresql`/`redis`/`kite`/`instrument_data` health checks. Also wires `MarketState`/`TickProcessor`/`MarketStateStore`/`SubscriptionManager`, exposes `sync_instruments()`, wires `underlying_discovery`/`expiry_service`/`option_chain_service` (Phase 5), and constructs `market_data_service` (Phase 6), registering it as a `TickProcessor` listener so candle aggregation runs off the live tick stream. **Phase 7's `StrategyEngine` is deliberately NOT wired in here** -- no instrument/strategy has been selected to trade yet (still a Phase 7+ decision), so nothing evaluates a strategy or generates a signal unless a caller explicitly constructs and starts a `StrategyEngine` itself. Contains explicit `TODO` markers for where Phase 8+ will add risk/order management. |
| `trading_system/health.py` | **(Phase 1)** `HealthCheck` is a small named-check registry (`register`/`run`); `build_default_health_check()` registers only the `application` check for now (`Application` registers `postgresql`/`redis`/`kite`/`instrument_data` separately). |
| `trading_system/engine.py` | `TradingEngine` builds Postgres/Redis/broker components and exposes an explicit `execute_trade_intent()` Phase 9 handoff after initialization. It never automatically executes a strategy signal; Phase 9 applies its own disabled-by-default safety gate. **(Phase 10)** Also builds a `ReconciliationEngine` and exposes `run_startup_reconciliation()`/`run_manual_reconciliation(scope)`/`start_periodic_reconciliation()`/`stop_periodic_reconciliation()`; none are auto-invoked. |
| `trading_system/main.py` | CLI entry point (`python -m trading_system.main`). Loads settings (fails fast on `ConfigurationError` before logging is even configured), configures logging, builds an `Application`, installs `SIGINT`/`SIGTERM` handlers, calls `start()`, logs the health check, blocks until a shutdown signal, then always calls `stop()` in a `finally` block. |
| `trading_system/broker/base.py` | `Broker` ABC -- `connect`, `get_instruments`, `subscribe`/`unsubscribe`, `place_order`/`modify_order`/`cancel_order`, `get_positions`/`get_orders`. Nothing outside `broker/` may import `kiteconnect`. |
| `trading_system/broker/kite_client.py` | **(Phase 4, extended Phase 6)** `KiteBroker`, the only `Broker` implementation, wrapping `kiteconnect.KiteConnect`. The access token is set on the underlying `KiteConnect` client eagerly in `__init__` (not only in `connect()`) so `health_check()`/`get_instruments()`/etc. all work correctly regardless of which method is called first. Retries `get_instruments()` on `BrokerConnectionError` with `tenacity`. `health_check()`, `login_url()`/`generate_access_token()`, and `_translate_kite_exception()` map every `kiteconnect.exceptions.*` error onto a typed `BrokerError` subclass. `get_historical_data()` (Phase 6) wraps `historical_data()`, mapping `interval_minutes` to Kite's interval strings -- deliberately not on the `Broker` ABC. |
| `trading_system/broker/websocket.py` | **(Phase 4)** `KiteWebSocketClient` wraps `kiteconnect.KiteTicker`, forwarding decoded ticks to a callback (normally `TickProcessor.process`). Tracks a `ConnectionState`, uses bounded reconnect (`KITE_MAX_RECONNECT_ATTEMPTS`), and restores active subscriptions after a reconnect. |
| `trading_system/market_data/tick_processor.py` | **(Phase 4, tightened Phase 6)** `MarketState` (thread-safe current/previous tick per instrument, plus `status()` for FRESH/STALE/UNAVAILABLE classification) and `TickProcessor` (validates ticks, updates state, optionally writes to a `MarketStateStore`, fans out to listeners, swallows per-listener/Redis exceptions). Validation now also rejects zero/negative price, negative volume/OI, and an impossible OHLC relationship. |
| `trading_system/market_data/instrument_sync.py` | **(Phase 4; extended)** `InstrumentSyncService.sync()` -- `Kite -> validation -> InstrumentRepository -> PostgreSQL`. Upserts by `instrument_token`, skips malformed records, and returns created/updated/skipped counts. Preserves zero lot/tick values for `INDICES` reference rows only; other instruments require positive values. |
| `trading_system/market_data/subscription_manager.py` | **(Phase 4)** `SubscriptionManager` -- tracks the active instrument-token subscription set through the `Broker`, making `subscribe`/`unsubscribe`/`unsubscribe_all` idempotent. Independent of strategy logic. |
| `trading_system/market_data/underlying_discovery.py` | **(Phase 5)** `UnderlyingDiscoveryService.discover()` resolves a symbol (e.g. `NIFTY`) to an `UnderlyingInstrument` from synchronized PostgreSQL data -- never re-downloads from Kite. `is_supported()` checks the actual synced instrument data, never a hardcoded allowlist -- works for any NSE F&O underlying (index or single-stock), not only NIFTY/BANKNIFTY. |
| `trading_system/market_data/expiry_service.py` | **(Phase 5)** `ExpiryService` -- `get_available_expiries`/`get_expiries_between`/`get_nearest_expiry`/`get_next_expiry`, reading real synchronized expiry dates (no fixed weekly/monthly assumption), using the application's IST clock so an expired contract is never "nearest". |
| `trading_system/market_data/option_chain_service.py` | **(Phase 5)** `OptionChainService` -- the option-chain/contract-lookup facade: `get_available_strikes`, `get_call_contract`/`get_put_contract`/`get_contract` (deterministic), `get_option_chain`. Optional Redis read-through cache; PostgreSQL always authoritative. |
| `trading_system/market_data/market_data_service.py` | **(Phase 6)** `MarketDataService` -- the market-data read/write facade: `on_tick()` feeds one `CandleAggregator` per configured interval; `get_current_candle`/`get_completed_candles` (in-memory), `get_cached_latest_completed_candle` (Redis), `get_candles` (PostgreSQL), `get_historical_data` (delegates to `HistoricalMarketDataProvider`). Persists/caches every completed candle automatically. |
| `trading_system/market_data/candle_aggregator.py` | **(Phase 6)** `CandleAggregator` -- per-instrument, per-interval OHLCV aggregation from ticks. Epoch-aligned candle boundaries, cumulative-to-delta volume conversion, late-tick rejection, and a completion-listener mechanism. |
| `trading_system/market_data/historical_data.py` | **(Phase 6)** `HistoricalMarketDataProvider` -- wraps `KiteBroker.get_historical_data()` and normalizes rows into `Candle` objects; raises `HistoricalDataError` on failure. Structural `Protocol` typing, never caches. |
| `trading_system/market_data/indicators.py` | **(Phase 6)** Pure, stateless technical-indicator functions (SMA, EMA, RSI, MACD, ATR, VWAP, Bollinger Bands) over `list[Candle]`; return `None` on insufficient data; `Decimal` arithmetic throughout. Never makes a trading decision. |
| `trading_system/market_data/instrument_manager.py` | `InstrumentManager` caches/looks up `Instrument` records from the broker's instrument dump (by token or trading symbol). |
| `trading_system/market_data/option_chain.py` | Builds a strikes-by-expiry option chain view on top of `InstrumentManager` for CE/PE lookups. |
| `trading_system/strategy/base.py` | `Strategy` ABC (Phase 1 scaffold, tick-driven, never wired anywhere): `on_tick`, `on_market_data`, `generate_signal() -> Signal | None`. **(Phase 7)** `BaseStrategy` ABC: `evaluate(context: MarketContext) -> StrategyDecision | None` -- the interface every real strategy implements going forward. |
| `trading_system/strategy/strategy.py` | `PlaceholderStrategy` (Phase 1, implements the old `Strategy` ABC) -- always returns `HOLD` (or `None`). Superseded by Phase 7's `BaseStrategy`/`NoOpStrategy` for anything context/candle-driven. |
| `trading_system/strategy/context.py` | **(Phase 7)** `MarketContext` -- the immutable per-evaluation snapshot (candles, current price, market status, strategy state, plus per-timeframe `confirmation_candles`) handed to a strategy. |
| `trading_system/strategy/decision.py` | **(Phase 7)** `StrategyDecision` -- a strategy's raw output before the engine turns it into a formal `Signal`. |
| `trading_system/strategy/config.py` | **(Phase 7)** `StrategyConfig` -- named, documented, testable per-strategy configuration (timeframe, cooldown, candle lookback, persistence toggle, `confirmation_timeframes_minutes` for multi-timeframe strategies). |
| `trading_system/strategy/no_op_strategy.py` | **(Phase 7)** `NoOpStrategy` -- the Phase 7 placeholder; never returns a decision. |
| `trading_system/strategy/patterns.py` | **(Phase 7)** Pure candlestick/indicator pattern detectors (engulfing, hammer/shooting star, morning/evening star, three soldiers/crows, trend structure, RSI/MACD/EMA-cross/Bollinger/VWAP) -- `Decimal`, never raises, `None` on no match. |
| `trading_system/strategy/scoring.py` | **(Phase 7)** `TechnicalScorer`/`ScoringConfig` -- multi-timeframe pattern confluence scoring (`-100..100`), threshold-based BUY/SELL, higher-timeframe trend veto. |
| `trading_system/strategy/technical_scoring_strategy.py` | **(Phase 7)** `TechnicalScoringStrategy` -- the `BaseStrategy` wrapping `TechnicalScorer`; a generic, reusable, production-standard alternative to `NoOpStrategy`. |
| `trading_system/strategy/signal_factory.py` | **(Phase 7)** `build_signal_dedup_key()`/`build_signal()` -- the only place a `Signal`'s deterministic identity and field-mapping are constructed; `instrument_token`/`tradingsymbol` come from `option_contract` when set, never the underlying's own. |
| `trading_system/strategy/option_selector.py` | **(Phase 7)** `OptionSelector` -- translates an underlying `BUY`/`SELL` signal into a concrete CE/PE `OptionContract` (ATM/OTM/ITM, nearest/min-days expiry) via Phase 5's `OptionChainService`/`ExpiryService`. Always buys (CE for `BUY`, PE for `SELL`) -- never writes/sells naked options. |
| `trading_system/strategy/signal_validator.py` | **(Phase 7)** `validate_signal()` -- pure validation function (no I/O), returns a list of failure reasons. |
| `trading_system/strategy/strategy_engine.py` | **(Phase 7)** `StrategyEngine` -- the orchestrator: candle-completion trigger, staleness gate, distributed lock, dedup, cooldown, option-contract resolution (`_resolve_option_contract`, optional `OptionSelector`), validation, persistence, state update. Terminates at "signal generated" -- never calls risk/order/broker code. |
| `trading_system/risk/risk_manager.py` | Phase 1 placeholder pipeline: `RiskManager.validate_signal()` enforces `RiskLimits` (max daily loss, max trades/day, max open positions), duplicate-signal detection, and a manual `emergency_shutdown()` kill switch. Daily counters roll over automatically at midnight. Unrelated to the Phase 8 `RiskEngine` below (different pipeline, kept for backward compatibility -- see [Phase 8](phases/phase-08-risk-position.md)). |
| `trading_system/risk/policy.py` | **(Phase 8)** `RiskPolicy` -- every limit defaults to `None` ("not enforced"); `from_settings()` builds one from `Settings`' `RISK_*` fields. |
| `trading_system/risk/risk_decision.py` | **(Phase 8)** `RiskCheckStatus`/`RejectionReason`/`RiskCheckOutcome`/`RiskDecision` -- the auditable result of one risk evaluation. |
| `trading_system/risk/account_state.py` | **(Phase 8)** `AccountState`/`AccountStateProvider`/`PostgresAccountStateProvider` -- exposure/P&L/position-count/daily-trade-count derived from durable PostgreSQL records; broker capital/margin always `None` (Phase 10). |
| `trading_system/risk/position_sizer.py` | **(Phase 8)** `PositionSizer` -- `Decimal`-precise, lot-size-floored quantity calculation from risk/capital/exposure/quantity limits. |
| `trading_system/risk/position_state.py` | **(Phase 8, extended Phase 9)** `PositionLifecycleStatus`/`RiskPositionStateStore` -- `NONE`/`PENDING`/`PARTIAL`/`OPEN`/`CLOSING`/`CLOSED` semantics layered on the Phase 3 `PositionStateStore`. |
| `trading_system/risk/risk_engine.py` | **(Phase 8)** `RiskEngine` -- the orchestrator: `Signal -> risk-check pipeline -> RiskDecision -> TradeIntent`. Never places an order; fail-safe on any storage/Redis failure. |
| `trading_system/risk/stop_loss.py` | **(Phase 8)** `StopLossCalculator`/`TargetCalculator` -- ATR-based (with percentage fallback) or points-based stop-loss, and a reward:risk-derived target. Fully configurable/disable-able via `RiskPolicy`. Both values are quantized to 2 decimal places (matching the `trade_intents.stop_loss`/`target` database columns) so the value computed here always matches what gets persisted and re-validated in Phase 9. |
| `trading_system/models/trade_intent.py` | **(Phase 8)** `TradeIntent`/`TradeIntentStatus` -- Phase 8's sole output, consumed by Phase 9. |
| `trading_system/storage/redis/risk_state.py` | **(Phase 8)** `RiskRuntimeStateStore` -- non-authoritative atomic daily counters + cooldown markers; PostgreSQL remains authoritative. |
| `trading_system/storage/redis/execution_state.py` | **(Phase 9)** `ExecutionRuntimeStateStore` -- expiring recent execution cache only; PostgreSQL remains authoritative. |
| `trading_system/execution/order_manager.py` | Legacy `OrderManager.submit_signal()` signal path retained for paper compatibility; it cannot access live broker submission. Phase 9 accepts persisted risk-approved `TradeIntent`s through `OrderExecutionEngine`. |
| `trading_system/execution/paper_executor.py` | `PaperExecutionHandler` -- simulates an instant `COMPLETE` fill at the signal/last-known price. Default handler; never talks to Kite. |
| `trading_system/execution/live_executor.py` | `LiveExecutionHandler` -- fail-closed compatibility stub; refuses legacy signal-based live submissions. |
| `trading_system/execution/order_request.py` | **(Phase 9)** Broker-neutral `OrderRequest`, execution lifecycle/result, and broker order snapshot types. |
| `trading_system/execution/broker_adapter.py` | **(Phase 9)** `BrokerOrderAdapter`, `KiteBrokerAdapter`, and fake paper adapter; the Kite adapter alone submits through the existing `Broker` abstraction. |
| `trading_system/execution/order_execution_engine.py` | **(Phase 9)** Validates persisted approved intents, gates live submission, uses durable idempotency/Redis locks, submits once, and records unknown/fill status. |
| `trading_system/execution/broker_status.py` | **(Phase 9, factored out in Phase 10)** `map_broker_status()`/`legacy_status_for()`/`LEGAL_STATUS_TRANSITIONS` -- the single broker-status classification Phase 9's `refresh_status()` and Phase 10's `OrderReconciler` both use, so they can never disagree. |
| `trading_system/execution/order_tag.py` | **(Phase 9, reused in Phase 10)** `build_order_tag()` -- the deterministic broker order tag Phase 9 submits and Phase 10 recomputes to resolve `SUBMISSION_UNKNOWN` without fabricating an association. |
| `trading_system/execution/position_manager.py` | `PositionManager.apply_fill()` opens/updates/closes `Position` objects keyed by instrument token as orders are filled; `mark_to_market()` updates unrealized P&L from ticks. |
| `trading_system/reconciliation/models.py` | **(Phase 10)** `ReconciliationResult`/`ReconciliationStatus`/`ReconciliationScope`, `OrderReconciliationItem`/`OrderReconciliationOutcome`, `PositionReconciliationItem`/`PositionReconciliationOutcome`, `ReconciliationResolution`. |
| `trading_system/reconciliation/policy.py` | **(Phase 10)** `ReconciliationPolicy` -- the centralized, explicit allow-list of safe auto-sync categories; `is_safe_position_quantity_sync()` encodes the "never auto-sync an unexpected quantity increase" rule. |
| `trading_system/reconciliation/order_reconciler.py` | **(Phase 10)** `OrderReconciler` -- compares `Broker.get_orders()` against persisted `orders`, including `SUBMISSION_UNKNOWN` tag-based resolution. Never calls a broker order-placement method. |
| `trading_system/reconciliation/position_reconciler.py` | **(Phase 10)** `PositionReconciler` -- compares `Broker.get_positions()` against persisted `positions` (or this application's own recorded fills, the first time). Never calls a broker order-placement method. |
| `trading_system/reconciliation/engine.py` | **(Phase 10)** `ReconciliationEngine` (locking, orchestration, audit persistence, Redis runtime refresh) and `PeriodicReconciliationScheduler` (opt-in background thread). |
| `trading_system/storage/postgres.py` | `PostgresClient` wraps a SQLAlchemy engine + session factory (`session()` context manager commits/rolls back automatically) and exposes `health_check()`. Schema changes go through Alembic, never `create_all()`. Redacts the DSN from any connection-error text before logging/raising. |
| `trading_system/storage/db/base.py` | **(Phase 2)** `Base` (SQLAlchemy `DeclarativeBase`), `utcnow()`, and `TimestampMixin` shared by all ORM models. |
| `trading_system/storage/db/models.py` | **(Phase 2; extended Phase 8/9/10)** ORM models include `Instrument`, `Signal`, `Order`, `Position`, `Trade`, risk decisions/intents, append-only Phase 9 execution attempts, and Phase 10's append-only `ReconciliationRun`/`OrderReconciliationRecord`/`PositionReconciliationRecord`. Separate from Pydantic domain models. |
| `trading_system/storage/db/repositories.py` | **(Phase 2, extended Phase 5/6/10)** `BaseRepository` + one repository per model (`InstrumentRepository`, `SignalRepository`, `OrderRepository`, `PositionRepository`, `TradeRepository`, `CandleRepository`, and Phase 10's `ReconciliationRunRepository`/`OrderReconciliationRecordRepository`/`PositionReconciliationRecordRepository`); operates on an injected `Session`, never manages transactions itself. `InstrumentRepository` gains discovery queries in Phase 5. `CandleRepository` (Phase 6) adds `get`/`list_range`/`save_if_new` (idempotent) for completed candles. `SignalRepository` (unchanged interface; the underlying `Signal` ORM gains a Phase 7 `status` column) persists Phase 7 signals via `create()`. |
| `trading_system/storage/redis/client.py` | **(Phase 3)** `RedisClient` -- pooled `redis.Redis` connection (explicit `ConnectionPool`), `health_check()`, and graceful `close()`/`dispose()`. Never opens a real connection until first used. |
| `trading_system/storage/redis/keys.py` | **(Phase 3)** `RedisKeyBuilder` -- the single place that builds namespaced Redis keys (`trading:{environment}:{kind}:{id}`); nothing else in the codebase builds raw key strings. |
| `trading_system/storage/redis/serialization.py` | **(Phase 3)** Explicit JSON `dumps`/`loads` helpers -- never `pickle`; `datetime`/`date` become ISO strings, `Decimal` becomes a string (exact precision preserved), `Enum` becomes its value. |
| `trading_system/storage/redis/state.py` | **(Phase 3)** `RedisStateManager` -- generic `set`/`get`/`delete`/`exists`/`expire`/`set_json`/`get_json`, wrapping every Redis error as `RedisUnavailableError`. All higher-level stores build on this. |
| `trading_system/storage/redis/lock.py` | **(Phase 3)** `DistributedLock` -- `acquire_lock`/`release_lock` using atomic `SET NX EX` plus a per-holder token checked via `WATCH`/`MULTI` on release, so a lock can never be released by a non-owner. TTL-bounded so a crashed process can never hold it forever. |
| `trading_system/storage/redis/dedup.py` | **(Phase 3)** `DeduplicationStore` -- atomic `check_and_mark`/`is_duplicate` (via `SET NX EX`) for duplicate signal/event protection. |
| `trading_system/storage/redis/market_state.py` | **(Phase 3)** `MarketStateStore` -- `set_latest_tick`/`get_latest_tick`/`delete_latest_tick`, always TTL'd (transient by nature). Storage interface only -- no Kite WebSocket wiring yet. |
| `trading_system/storage/redis/strategy_state.py` | **(Phase 3)** `StrategyStateStore` -- `get_state`/`set_state`/`update_state`/`clear_state` for opaque per-strategy runtime state, no TTL by default. |
| `trading_system/storage/redis/position_state.py` | **(Phase 3)** `PositionStateStore` -- fast-access `get_position`/`set_position`/`delete_position` cache; PostgreSQL remains the authoritative position store. |
| `trading_system/storage/redis/cache.py` | **(Phase 3)** `CacheStore` -- generic, explicit-purpose `set`/`get`/`delete` with a default TTL, for instrument/option-contract/derived-data caching. |
| `trading_system/storage/redis/option_chain_cache.py` | **(Phase 5)** `OptionChainCacheStore` -- `get_option_chain`/`set_option_chain`/`delete_option_chain`, keyed by `RedisKeyBuilder.option_chain(underlying, expiry)`, TTL'd (60s default). A performance cache only -- PostgreSQL remains authoritative. |
| `trading_system/storage/redis/candle_cache.py` | **(Phase 6)** `CandleCacheStore` -- `get_latest_completed_candle`/`set_latest_completed_candle`/`delete_latest_completed_candle`, keyed by `RedisKeyBuilder.candle(instrument_token, interval_minutes)`, TTL'd (300s default). Caches only the latest *completed* candle, never the forming one. |
| `trading_system/storage/s3.py` | `S3Client` wraps `boto3` S3 operations for snapshot/archival storage; exposes `health_check()`. |
| `trading_system/models/*.py` | Pydantic v2 models: `Tick`, `Instrument`, `OptionContract` (Phase 5 -- `Decimal` strike/tick_size), `Candle` (Phase 6 -- `Decimal` OHLC, mutable), `Signal` (+ `SignalType`), `Order` (+ `OrderStatus`/`OrderType`/`ProductType`/`TransactionType`), `Position` (+ `PositionStatus`). These are the only data shapes passed between layers. |
| `trading_system/backtest/models.py` | **(Phase 11)** `BacktestConfig`, `BacktestResult`, `BacktestStatus`, `TradeRecord`, `DataQualityWarning`, `ExecutionModelConfig`, `PaperSessionStatus`. |
| `trading_system/backtest/costs.py` | **(Phase 11)** `TransactionCostModel` -- every rate defaults to zero/`verified=False`; never an invented real fee schedule. |
| `trading_system/backtest/data_loader.py` | **(Phase 11)** `HistoricalDataLoader` -- prefers PostgreSQL candles, falls back to the existing Phase 6 `HistoricalMarketDataProvider`; validates ordering/duplicates/missing intervals/invalid OHLC. |
| `trading_system/backtest/execution_adapter.py` | **(Phase 11)** `BacktestExecutionAdapter`/`PaperExecutionAdapter` -- implement the existing Phase 9 `BrokerOrderAdapter` interface with documented, conservative simulated fills; never call a real broker. |
| `trading_system/backtest/portfolio.py` | **(Phase 11)** `Portfolio` -- Decimal cash/position/realized-unrealized-P&L/equity/drawdown accounting with explicit averaging/reducing/closing/reversal rules. |
| `trading_system/backtest/metrics.py` | **(Phase 11)** Win rate/profit factor/consecutive win-loss/Sharpe/Sortino -- every metric is `None`, never fabricated, when the data is insufficient. |
| `trading_system/backtest/engine.py` | **(Phase 11)** `BacktestEngine` -- wires the real, unmodified Phase 7/8/9 engines against an isolated per-run SQLite database + in-memory Redis and a simulated clock. |
| `trading_system/backtest/paper.py` | **(Phase 11)** `PaperTradingSession` -- the same engines driven by live candle-completion events instead of a historical loop; session lifecycle persisted to `paper_sessions`. |
| `trading_system/utils/logger.py` | `configure_logging()` installs a `JsonFormatter` on the root logger (single-line JSON per log record: timestamp, level, component, event, extra fields). `Event` centralizes canonical event-name string constants used across the app. |
| `trading_system/utils/time_utils.py` | NSE market-time helpers: `now_ist()`, `is_trading_day()`, `is_market_open()`, `market_open_datetime()`/`market_close_datetime()`, holiday handling, and `to_utc()` (Phase 6 -- the single place naive-vs-aware timestamp ambiguity is resolved for candles/indicators/historical data; a naive datetime is assumed to already be IST). Uses `zoneinfo.ZoneInfo("Asia/Kolkata")`, which requires the `tzdata` package on Windows. |
| `trading_system/exceptions/__init__.py` | Exception hierarchy rooted at `TradingSystemError`: `ConfigurationError`, `BrokerError` (→ `BrokerAuthenticationError` → `BrokerTokenExpiredError`, `BrokerAuthorizationError`, `BrokerConnectionError`, `BrokerTimeoutError`, `BrokerRateLimitError`, `InvalidBrokerRequestError`, `BrokerUnavailableError`), `WebSocketError`, `InstrumentNotFoundError`, `InstrumentSyncError`, `UnderlyingNotFoundError`, `ExpiryNotFoundError`, `StrikeNotFoundError`, `ContractNotFoundError`, `InvalidOptionTypeError`, `InvalidInstrumentDataError`, `DuplicateContractError` (Phase 5), `HistoricalDataError` (Phase 6), `OrderError` (→ `DuplicateOrderError`), `RiskLimitError`, `StorageError` (→ `RedisUnavailableError`). Phase 7 deliberately adds no new exception type -- signal validation returns a list of reason strings instead of raising (a rejected signal is an everyday outcome, not an error). |
| `scripts/health_check.py` | CLI that checks Postgres, Redis, and Kite connectivity and exits non-zero if any check fails. |
| `scripts/download_instruments.py` | CLI that downloads Kite instruments and upserts them into PostgreSQL via `InstrumentSyncService`; no arguments sync both `NFO` and `NSE`, while one or more exchange arguments select a subset. |
| `scripts/reconcile.py` | **(Phase 10)** CLI that triggers manual reconciliation (`--scope all\|orders\|positions`) via `TradingEngine.run_manual_reconciliation()` and exits non-zero unless the result is `CONSISTENT`/`RECONCILED`. |
| `scripts/backtest.py` | **(Phase 11)** CLI that runs a backtest (`--strategy no_op\|technical_scoring --instrument-token ... --start/--end YYYY-MM-DD --initial-capital ...`) and exits non-zero unless the result is `COMPLETED`. Clears the trading-window/session-edge risk settings before running, since those compare against the real wall clock, not simulated candle time -- see the [How-To Guide](how-to.md#how-to-run-a-backtest). |
| `scripts/paper_trade.py` | **(Phase 11)** CLI that starts (foreground, `Ctrl+C` to stop, `--strategy no_op\|technical_scoring`) or inspects the status of a paper-trading session. See the [How-To Guide](how-to.md#how-to-run-paper-live-trading). |
| `scripts/run_dashboard.py` | **(Phase 11 addendum)** CLI that serves the dashboard (`uvicorn`, `--host`/`--port`/`--reload`). See the [How-To Guide](how-to.md#how-to-view-the-dashboard). |
| `trading_system/api/app.py` | **(Phase 11 addendum)** `create_app()`/module-level `app` -- builds the FastAPI dashboard app: a `GET /` route that server-renders `frontend/templates/index.html` via Jinja2, read APIs plus token-protected settings writes under `/api`, and mounts `frontend/static/` (CSS/JS) at `/static`. |
| `trading_system/api/dependencies.py` | **(Phase 11 addendum)** Process-wide `PostgresClient`/`RedisClient`/`KiteBroker` singletons (`lru_cache`d) and a per-request `get_db_session()` dependency -- reuses the exact same `config.settings.get_settings()` the rest of the application uses, never a second connection mechanism. |
| `trading_system/api/serialization.py` | **(Phase 11 addendum)** `row_to_dict()`/`rows_to_list()` -- generic ORM-row-to-JSON-dict conversion via `sqlalchemy.inspect()` + FastAPI's `jsonable_encoder`, instead of a hand-written Pydantic schema per table. Relationships are never included, only mapped columns. |
| `trading_system/api/queries.py` | **(Phase 11 addendum)** `list_recent()` (generic, bounded, most-recent-first), `instrument_extras_by_row_id()` (batched instrument lookup so a response never shows a bare instrument UUID), `list_candles()`. |

| `trading_system/api/routers/market.py` | **(Phase 11 addendum)** `GET /api/instruments` supports partial case-insensitive symbol/name search, exact underlying, exchange/type filters, stable `limit`/`offset` pagination (maximum 500), and `X-Total-Count`; also serves `/instruments/{token}` and `/candles`. |
| `trading_system/api/routers/trading.py` | **(Phase 11 addendum)** `GET /api/signals`, `/orders`, `/positions`, `/trades`, each instrument-enriched. |
| `trading_system/api/routers/risk.py` | **(Phase 11 addendum)** `GET /api/risk-decisions`, `/trade-intents`. |
| `trading_system/api/routers/reconciliation.py` | **(Phase 11 addendum)** `GET /api/reconciliation-runs`, `/{id}`, `/{id}/orders`, `/{id}/positions`. |
| `trading_system/api/routers/backtests.py` | **(Phase 11 addendum)** `GET /api/backtest-runs`, `/{id}`, `/{id}/trades`, `/paper-sessions`. |
| `trading_system/api/routers/dashboard.py` | **(Phase 11 addendum)** `GET /api/scores`, `GET /api/dashboard/metrics`, `GET /api/dashboard/settings`, and token-protected `PUT /api/dashboard/settings`; settings are allow-listed, validated, and audited. |
